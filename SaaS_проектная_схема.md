# Флюкс | СИС — единая SaaS-схема

## 1. Главная идея: «Проект» как единственная сущность

Вместо набора отдельных экранов (лендинг, калькулятор, менеджер, монтажник, клиент)
весь продукт строится вокруг одной сущности — **Проект** (объект: стены, потолок, проёмы,
текстиль). Каждая роль — это *взгляд и права* на один и тот же проект, а не отдельная программа.

```
        ┌───────────────────────────  ПРОЕКТ  ───────────────────────────┐
        │                                                               │
        │   walls[]  ceiling  opening[]  textile  photos  documents     │
        │   ценовой уровень · статус · владелец · команда               │
        └───────┬────────┬────────┬─────────┬────────┬──────────────────┘
                │        │        │         │        │
             Дизайнер  Дилер   Монтажник  Менеджер  Клиент
```

**Принцип:** один проект создаётся один раз и последовательно проходит по цепочке ролей,
каждая граня видит только свои цены и свои действия. Никакой пересметы и копипаста между
таблицами.

---

## 2. Роли и их грани (одна страница на роль)

| Роль | Страница | Что делает | Ценовой уровень | Права на проект |
|---|---|---|---|---|
| **Дизайнер** | `designer.html` *(новая)* | создаёт объект, подбирает ткани/потолок, делает эскиз и КП | розница `/дизайнерский прайс` | создать, редактировать |
| **Клиент** | `client.html` | оплачивает, следит за статусами, видит смету и КП | розница | читать свой проект |
| **Дилер** | `dealer.html` *(новая)* | закупает «Юнит», видит маржу, заказывает материалы | закупочные `iksCompany` | проект своей сети |
| **Монтажник** | `installer.html` | раскрой, BOM, чек-лист, фотоотчёт, сдача | себестоимость | принять / сдать |
| **Менеджер** | `manager.html` | CRM лида, права, цены, смета | всё + наценки по каналам | все |

Права текущей роли выдаёт сервер при входе (эндпоинт `/api/auth/role` уже есть) — один
`login.html`, дальше система открывает нужную грань.

---

## 3. Жизненный цикл проекта (статусы)

Один набор статусов сквозь все роли. Три ценовых колонки — одна смета:

```
 UNIQUE_ID  →  DESIGN  →  QUOTED  →  PAID  →  SUPPLY  →  INSTALL  →  DONE  →  ARCHIVE
     дизайн     КП выдано  предоплата    закупка    монтаж    сдача
```

| Статус | Активная роль | Действие | Побочные таблицы |
|---|---|---|---|
| `design` | дизайнер | раскладка стен, подбор | stens, textile |
| `quoted` | дизайнер → клиент | формирует КП (PDF) | quote |
| `paid` | клиент / менеджер | оплата, фикс. тариф | deal |
| `supply` | дилер / менеджер | закупка, BOM, сроки | task |
| `install` | монтажник | раскрой, чеклист, фото | task + photo |
| `done` | монтажник → клиент | акт, гарантия 30 лет | act |

Задача-«СМС уведомления» при смене статуса в уже есть в `notify.js` и CRM `tasks`.

---

## 4. Один движок расчёта — три ценовых столбца

Сейчас расчётный движок уже отдельный (`iks-calculator.js`, `combined.js`, `walls/calculate`).
Его нужно поднимать **одинаково** из всех ролей, разница только в том, какие цены подставлять.

```
 buildEstimate( walls, pricingLevel )  →  { body, units, rezie, bom }
```

| Уровень | Откуда цены | Кто 'на самом деле использует |
|---|---|---|
| `retail` | `prices.js` / `pricePerM2` | клиент, дизайнер |
| `distributor` | `iksCompany` (`/api/prices/iks-company`) | дилер — маржа +30–50% |
| `cost` | `iksInstall` (`/api/prices/iks-install`) | монтажник |

Смета одна, колонки цен подставляются по `pricingLevel` авторизованного пользователя.
Никакого дублирования «двух калькуляторов» — на фронте одинаковая выкладка, бэк лишь меняет
сдвиг цен.

## 5. Справочники (единые)

- Цены СИС: `/api/prices/sis` — компоненты MSD, ID System (скрытый каркас), Tönlos Heavy Felt 13 мм;
- Цены потолков/опций/профиля: `prices.js`;
- Наценки: `crm` / `prices` per-канал;
- Ткани: 200+ оттенков из текстильного прайса (общий список).

Все граню роля открывают один и тот же справочник — только права на запись различаются.

## 6. Так что уже есть и что добавить (дорожная карта честная)

| Пункт | Статус | Действие |
|---|---|---|
| Движок расчёта (СИС/потолки/комплекс) | ✓ есть | ничего |
| Движок раскроя + BOM | ✓ есть | `installer` уже экспортирует PDF/XLSX |
| CRM лидов/сделок/задач | ✓ есть | `manager` |
| Экспорт | ✓ есть | `export.js` |
| **Сущность `project`** | не в БД | добавить таблицу `projects` + `project_items` |
| **Бирь общей роли** | фрагм. | оформить `PHAS = {designer, dealer}` и роутинг |
| **единый вход по роли** | /api/auth/role есть | расширить макросы ролей |
| **страница дизайнера / дилера** | нет | добавить 2 страницы-грани |
| **переход проекта по цепочке** | нет | `PATCH /api/project/:id/status` |
| **SMS** | заглушка | реальная интеграция |

`installer.html` и `manager.html` уже реально работают на сервере — их не ломаем, а навешиваем
на общую сущность.

---

## 7. Критерий «логично объединили»

- Один пользователь входит один раз → видит только свою грань.
- Один проект → движется по цепочке ролей без пересылки данных.
- Один расчёт → три ценовые колонки, а не три калькулятора.
- Любая роль экспортирует PDF/XLSX из того же проекта (одна кнопка).

Если всё это выполняется — SaaS логически един и склеен. Готово к реализации по шагам.
